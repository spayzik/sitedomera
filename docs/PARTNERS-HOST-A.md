# ДЕКОРАЙ Партнёрам · подключение Host-A

## Перед включением

Публикуемая статическая часть включает /partners/, /partners/dealers/, /partners/agents/ и /partners/dropshipping/. Существующие /opt/ и /dizayneram/ ведут к форме проекта. Страницы кабинета и менеджера закрыты метатегом, исключены из sitemap и IndexNow. Без PHP на GitHub Pages доступны описание программ и способы связи.

1. Возьмите production ZIP для проверенного коммита. Проверьте SHA-256 и сохраните действующие webroot, конфигурацию, снимки и SQLite. Разложите web/, api-entry/ и private-runtime/ по схеме [RELEASE-PROFILES.md](RELEASE-PROFILES.md). Новый публичный entry — api/partners.php. Приватные модули и данные располагаются в dekoray-leads вне webroot.
2. Сверьте фактические PHP 8.3+, PDO SQLite, OpenSSL, mbstring, DOM и TLS FastCGI на Host-A. Установите доступ только для пользователя приложения, 0700 для директорий, 0600 для конфигурации и БД. Изолируйте тестовую БД от боевой. По умолчанию partners.json отсутствует и API возвращает 503.
3. Сохраните partners.json вне webroot. Укажите `enabled`, канонический HTTPS `origin`, случайный ключ `key` из 32 байт hex, утверждённые `consentVersion`, `consentPath`, `consentSha256`. Для атрибуции отдельно утвердите и задайте `attribution: {version, ttlDays, priority}`. Поддерживаются `first_confirmed` и `manager_conflict`. Без политики регистрация партнёрского кода закрыта. Значения и сроки поступают из утверждённой программы.
4. Примените только утверждённые Apache rewrite и маршрутизацию HTTPS. Проверяйте Origin, CSRF, cookie Secure/HttpOnly/SameSite, выдачу no-store и разделение ролей в отдельной среде. Проверьте, что прямой публичный URL файлов конфигурации, SQLite, CLI и private-runtime закрыт. Не публикуйте папку state.
5. Подготовьте ответственного сотрудника. Приватно создайте учётную запись командой `php partner-cli.php provision <document-root>`, передав на stdin JSON с `email,password,role`, а для партнёра ещё `partnerId`. Менеджер не получает доступ к административным операциям. Доставку начального пароля согласуйте отдельно. Проверяйте права после выдачи и отзыва.
6. Оператор проверяет связи с заказами в МойСклад read-only. Новый код не создаёт контрагента, заказ, резерв или выплату. Сценарий записи требует отдельного Owner GO. По API МойСклад предусмотрены дополнительные поля заказов, группы контрагентов и типы цен. Идентификаторы согласованных полей, групп, состояний и цен получите из кабинета. [JSON API МойСклад](https://dev.moysklad.ru/doc/api/remap/1.2/)

## Работа менеджера

1. Откройте /partners/manage/ и войдите с ролью менеджера. Проверьте заявку, направление, позиции, объём и город. Подтвердите условия и их версию или отклоните заявку.
2. Сохраните индивидуальные условия с датой начала и уровнем, если он предусмотрен договором. Добавьте согласованный текстовый прайс или CSV только в документы этого партнёра. Регистрация заявки сама по себе не открывает кабинет. Пароли создаёт доверенный оператор CLI.
3. Проверьте запрос на поставку и его статусы. Для перепродажи без склада оформляйте документы на отгрузку только после согласования сторон сделки и основания для передачи адреса. Для агентской модели заведите подтверждённое обращение. Сверяйте конфликтующие заявки через журнал и выберите победителя в рамках утверждённой политики.
4. Свяжите подтверждённое обращение или согласованный запрос партнёра с существующим заказом. Перед сохранением сравните клиента, контрагента и заказ в МойСклад. Идентификатор один на заказ. Партнёр видит только своё.
5. После подтверждения оплаты выполните частную сверку `php partners-operations-cli.php reconcile <document-root>`. Политика `partner-sales-policy.json` хранит массив rules за пределами webroot. Правило содержит `approved`, `version`, `from`, `to` (Unix seconds), `rateBps`, `holdDays`, `programs` и `base`. База `order_total` включает весь допустимый платёж, `goods_less_all_refunds` исключает доставку и вычитает полную сумму возврата из товарной части. Включайте только ту схему, которая прямо согласована. Несовместимую формулу отправляйте на уточнение.
6. Повторите сверку после возврата. Система хранит изменение начисления и ранее подтверждённую выплату. Если возникла переплата, договоритесь о порядке корректировки с бухгалтерией. Новый перевод проводят отдельно, после проверки итогов и выдержки. В кабинете отмечается только фактически подтверждённая оплата вознаграждения, с суммой и неперсональным номером подтверждения.

## Атрибуция и аналитика

ClientID, yclid и разрешённые UTM учитываются после согласия на аналитику. Партнёрский код хранится отдельно. На открытие формы и посещение по ссылке конверсия продажи не отправляется. После первого подтверждённого приёма формы доступно пять целей `wholesale_request`, `dealer_request`, `partner_application`, `designer_request`, `dropshipping_request`. В серверной выгрузке доступны `referral_lead_confirmed` и `partner_sale_confirmed`.

Для существующих заявок передача в МойСклад включается только проверенной картой `marketingFields` в config.json. Ключи `clientId`, `yclid`, `source`, `medium`, `campaign` сопоставляются с UUID согласованных строковых полей заказа. Перед включением проверьте полномочия и типы полей на отдельном тестовом контуре. Назначение клиентских данных и срок хранения утверждает Owner.

Экспорт выполняет доверенный сотрудник: `php partners-operations-cli.php offline <document-root> <from-unix> <to-unix> > <private-file.csv>`. Интервалы полуоткрытые, до 21 дня. После подтверждения импорта в отдельном кабинете сохраните дату, диапазон и квитанцию. Не пересекайте уже принятый диапазон. CSV временно хранится в закрытом каталоге. Выгрузка не содержит email, телефона или партнёрского кода. Привязку и фактическую регистрацию целей проверьте в отчёте кабинета. [Формат офлайн-конверсий](https://www.yandex.ru/support/metrica/ru/data/offline-conversion-data)

## Rollback

Сначала отключите partners.json и остановите частную сверку. Верните прежние файлы и Apache-конфигурацию из резервной копии. SQLite партнёрских начислений и историю выплат сохраните отдельно, с владельцем доступа. При восстановлении проверьте уникальность ссылок на заказы и сравните актуальные подтверждения оплат и возвратов.
