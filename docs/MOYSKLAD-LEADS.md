# Заявки из корзины и МойСклад

Статус — `MOYSKLAD_HOLD`. На статическом сайте открываются Telegram и телефон. Форма появляется только с настроенным HTTPS API и опубликованным отдельным согласием той же версии. Действующие политика и согласие должны описывать новое обращение, передачу и обработку данных. Ответственный за обработку, срок хранения и права доступа утверждает владелец.

Используется [МойСклад JSON API 1.2](https://dev.moysklad.ru/doc/api/remap/1.2/). Сначала менеджер сверяет схему: организация, статус входящей заявки и сопоставление всех позиций сайта. Адаптер создаёт непроведённый `customerorder` с выбранным статусом. Поля резерва, оплаты и отгрузки не передаются. Заявка принимается после ответа с UUID сущности, её типом, ожидаемым `syncId` и `applicable: false`. Эта схема проверена через подставной API. Реальный порядок обработки заказов и клиента должен подтвердить владелец кабинета.

## Проверка доступа

Передать новый или действующий токен только через секреты серверного рантайма. Ни в сборке сайта, ни в браузерных настройках его быть не должно.

```sh
node server/leads/run.mjs access-preflight
node server/leads/run.mjs preflight
```

Первая команда выполняет только GET для организаций, метаданных статусов заказов и ассортимента. Она показывает видимость и количество доступных статусов, не выводит записи или значения токена. Вторая команда сверяет конкретные UUID организации, статуса и картотеку товаров после заполнения конфигурации. Доступ на запись и поведение живого заказа подтверждаются отдельно, только на согласованной тестовой заявке.

## Сервис

Запускать `node server/leads/run.mjs` на Node.js 24. На статический хостинг загружается только `dist/`. Сервис нужно разместить отдельно и привязать по HTTPS к маршруту `/api/lead`. Он слушает только IPv4 loopback. Подключить TLS на обратном прокси, ограничить размер тела запроса 16 КБ, оставить тайм-аут прокси не меньше 15 с и не логировать тела, публичные ключи повторов или заголовки авторизации. Если прокси проверен и переписывает `X-Dekoray-Client-IP` своим фактически наблюдаемым адресом клиента, включить `DEKORAY_TRUST_LOCAL_PROXY=1`. По умолчанию клиентский заголовок игнорируется. При отдельном API-хосте разрешить его в `connect-src` сайта. Публичная сборка принимает только `/api/lead` или HTTPS URL с этим путём в `VITE_DEKORAY_LEAD_API`.

Переменные на стороне сервера:

- `DEKORAY_SITE_ORIGIN` — точный подтверждённый HTTPS origin без завершающего слеша.
- `MOYSKLAD_API_TOKEN`, `MOYSKLAD_ORGANIZATION_ID`, `MOYSKLAD_INTAKE_STATE_ID` — серверный токен и подтверждённые UUID.
- `DEKORAY_CATALOG_MAP_FILE` — абсолютный путь к закрытому JSON. Каждый идентификатор товара сайта имеет запись с `type` (`product`, `variant` или `bundle`), `id` (UUID) и `priceMinor` (проверенная цена в копейках). Сверять при обновлении каталога. Суммы из браузера отвергаются.
- `DEKORAY_CONSENT_PATH` — путь отдельного согласия, например `/legal/lead-consent.html`. Опубликованный HTML должен содержать `<meta name="dekoray-consent-version" content="...">` со значением `DEKORAY_CONSENT_VERSION`.
- `DEKORAY_LEAD_LEDGER_PATH` — абсолютный путь файла SQLite на постоянном диске вне webroot. Бэкапить журнал и ключ вместе в закрытом контуре.
- `DEKORAY_LEAD_LEDGER_DAYS` — утверждённый срок хранения журнала (от 1 до 365 дней).
- `DEKORAY_LEAD_HMAC_KEY` — 32 случайных байта в hex. Смена ключа меняет коды синхронизации и требует отдельного перехода с учётом незавершённых заявок.
- `DEKORAY_LEAD_PORT` — локальный порт за прокси (по умолчанию 8787).
- `DEKORAY_ENABLE_LEADS=1` — включать после готовности сервиса, проверки маршрута и публикации согласия и политики.

## Повторы и подтверждение

Сервер ограничивает частоту запросов и принимает только разрешённый Origin. Поддельные поля, цена или товар вне подтверждённого сопоставления отвергаются. Пустое поле-ловушка обязательно. При сетевой ошибке адаптер прекращает попытку, оставляя право повторить тот же запрос с тем же ключом. Транзакционный журнал хранит HMAC идентификатора и нормализованного запроса, время и версию согласия и номер обращения. В течение 15 минут совпадающие нормализованные данные переиспользуют операцию даже после перезагрузки с новым ключом. Повтор с тем же ключом и изменёнными данными получает 409 в пределах срока хранения. Данные формы и источник запроса не записываются в технические логи. Управление сроком хранения самих обращений и контактов выполняется в МойСклад.

Телефон нормализуется. Если найден единственный существующий контрагент по точному номеру, заказ прикрепляется к нему. Несколько совпадений требуют ручной проверки. Контрагентам и заказам назначаются стабильные `syncId`, чтобы повтор после неопределённого результата обращался к той же сущности. Проверьте, что прежние номера в кабинете приведены к одному формату. При ошибке МойСклад возможен уже созданный контрагент без заказа. Менеджер может проверить такие записи без повторного создания контакта.

Локальная проверка. `node --test server/leads/http.test.mjs` использует настоящий HTTP на loopback, временную SQLite и подставной API МойСклад.

## Кандидат W7 для PHP

PHP 8.3 и расширения cURL, PDO SQLite, mbstring, intl, DOM и OpenSSL с AES-256-GCM требуются в веб-рантайме и в CLI. Собирать закрытый и публичный наборы с помощью `scripts/package-host-a.ps1`. Файл `api-entry/lead.php` размещается как `api/lead.php` за существующим маршрутом `/api/lead`. Модули, конфигурация, каталог и каталог `state` остаются вне webroot. Утверждённый документ согласия должен совпасть по версии и SHA-256. Ключ, организация, статус, отдельный подтверждённый контрагент входящих заявок (intakeAgentId) и карта позиций настраиваются только в закрытом контуре. Клиентские контакты передаются в закрытом описании заявки. Для PHP поиск или создание контрагентов по номеру телефона исключён. Изменение контрагента требует проверки незавершённых заявок.

Доступны консультация, подбор, расчёт, образцы, запрос заказа, монтаж и замер, доставка, оптовые условия, дизайнерская программа и обратная связь. В обращении с составом сервер проверяет идентификаторы каталога и количество. Для запроса расчёта сервер принимает размеры стен, площадь проёмов, запас и метод, рассчитывает количество листов и стоимость по каталогу. Для расчёта по вертикальной раскладке проёмы должны быть нулевыми. Формы запроса заказа создают непроведённое обращение с артикулами и количеством в описании. Проверенная корзина через прежний контракт требует сопоставленных позиций и использует цены сервера.

SQLite хранит зашифрованный черновик до подтверждения получателем. Обе попытки, через повтор в браузере и через фоновый запуск, используют один идентификатор и общую блокировку. Без подтверждения получателем ответ остаётся 503 либо 409 при активной попытке. После подтверждения одинаковый запрос возвращает ту же квитанцию. Работник обрабатывает до пяти готовых заявок за запуск, откладывает повтор на срок до часа, удерживает запись после 12 ошибок или изменения согласия или сопоставления. Просроченные зашифрованные данные удаляются по утверждённому сроку. Бэкап конфигурации, журнала и HMAC-ключа должен храниться в закрытом контуре. Замена ключа требует отдельной миграции, чтобы сохранить возможность повторной доставки.

Включать после допуска владельца, проверки TLS, PHP, доступа к закрытому диску и точного документа согласия. После подтверждения отсутствия автоматических резервов и движений выполнить закрытый read-only preflight из Host-A. Проверить, что CLI видит ту же PHP-конфигурацию и те же права. Затем согласовать запуск следующей команды из планировщика раз в минуту от пользователя сайта.

```sh
php /private/dekoray-leads/retry.php /path/to/webroot --deliver
```

CLI выводит только число принятых, отложенных, удержанных и просроченных заявок. Для удержанных записей владелец назначает действий оператору закрытого контура.

### Изолированная проверка staging

```sh
npm run test:leads:php
npm run test:inventory
npm run test:avito
```

PHP-тесты используют реальный HTTP на loopback, отдельные временные SQLite и тестового получателя. Для тестового стенда запустить `node server/leads-php/test/staging.mjs` с отдельно переданным случайным `DEKORAY_STAGING_TEST_ACCESS` длиной от 32 символов и `DEKORAY_STAGING_PORT` (по умолчанию 8789). Рабочие токены в этом процессе не нужны. Прокси должен использовать отдельное разрешённое тестовое имя с HTTPS, проксировать только `/api/lead` и `/legal/lead-consent.html`, ограничивать тело и частоту запросов, скрывать заголовок доступа в логах и возвращать CORS для точного origin `https://spayzik.github.io`. Синтетический запуск хранит тестовые подтверждения до штатной остановки, после которой временный каталог удаляется. Команда использует тестовый рантайм и не входит в production ZIP.

В браузерную сборку передаётся только HTTPS URL тестового API. Разрешённый тестер вводит код доступа в форму, используя имя «Тест Декорай», номер `+12025550101` и при необходимости `dekoray@example.test`. Сервер удаляет свободный текст из доставляемых тестовых заявок. Завершение локальных тестов подтверждает работу синтетического маршрута. Для публичной проверки требуется отдельно доступный тестовый HTTPS-хост.
