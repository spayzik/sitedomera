# Подключение поиска ДЕКОРАЙ

## Подтверждение прав

Сначала проверьте существующие свойства production-домена в кабинетах. Если право уже подтверждено через DNS, сохраните эту запись и добавьте нужных пользователей. Не требуется менять метод подтверждения. Публичный preview остаётся закрытым от индексации.

Если подтверждение через веб-сайт требуется, укажите полученные от кабинета файлы в `DEKORAY_YANDEX_VERIFICATION_FILE` и `DEKORAY_GOOGLE_VERIFICATION_FILE`. Передайте абсолютные пути к оригинальным файлам. Либо задайте значения атрибута content через `DEKORAY_YANDEX_VERIFICATION_META` и `DEKORAY_GOOGLE_VERIFICATION_META`. Production-сборка положит файлы в webroot и добавит метатеги главной. При смене webroot сохраните все действующие файлы подтверждения, даже если текущий релиз не генерирует их. DNS и кабинеты сборка не меняет. Для доменного свойства Google требуется подтверждение DNS. [Google Search Console](https://support.google.com/webmasters/answer/9008080?hl=en)

После размещения и проверки домена:

1. В Яндекс Вебмастере добавьте sitemap.xml и свяжите сайт с существующим счётчиком Метрики. В разделе «Представление в поиске → Региональность» предложите Москву и приложите страницу шоурума с действующим адресом. Дождитесь решения модерации. [Региональность](https://www.yandex.ru/support/webmaster/ru/site-geography/site-region)
2. В Search Console отправьте тот же production sitemap.xml для подтверждённого свойства. Проверьте корневой адрес, категории и товары через URL Inspection.
3. Для Поиска по товарам подключите production `/yml.xml` в разделе товарных фидов с соответствующим регионом. Проверьте обработку и диагностику. Для Директа используйте отдельный `/yml-direct.xml`. [Товарные фиды](https://yandex.ru/support/webmaster/ru/feed/upload.html)

## IndexNow

Если у магазинов уже есть утверждённый ключ IndexNow именно для production-домена, задайте его через `DEKORAY_INDEXNOW_KEY` и для сборки, и для команды ниже. Без переопределения production-профиль использует сгенерированный публичный ключ ДЕКОРАЙ. Это публичный файл владения, отдельный от ключей кабинетов и секретов интеграций.

До замены webroot сохраните `indexnow-release.json` текущего выпуска вне webroot. После загрузки нового выпуска выполните как обязательный шаг штатного сценария публикации:

```sh
node scripts/indexnow.mjs --release /path/to/previous-indexnow-release.json /path/to/new-indexnow-release.json
```

При первом выпуске с этим механизмом используйте `--first` вместо пути к предыдущему файлу. Отправка опирается на контрольные суммы страниц и список их канонических путей. Она также включает пути, удалённые из предыдущего выпуска. Команда сверяет опубликованный список и файл владения по production HTTPS. При расхождении она завершится ошибкой без отправки. Для повторного запуска после сбоя сохраните обе версии списка до ответа 200 или 202. Эти ответы подтверждают приём уведомления. Индексация проверяется отдельно в кабинете. [Протокол IndexNow](https://www.indexnow.org/documentation)
