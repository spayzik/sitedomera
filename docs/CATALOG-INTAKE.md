# Каталог · добавление подтверждённых позиций и проектов

Действующий каталог объединяет 46 проверенных строк PDF и дополнительный согласованный реестр. Опубликовано 45 позиций, строка p11 r2c2 ожидает идентификации. Архив витрины и непроверенные старые изображения не добавляют ассортимент автоматически. Действующая синхронизация МойСклад остаётся источником складской информации.

## Импорт новых позиций

Файл владельца хранится вне webroot и репозитория. Подготовьте JSON со структурой `{ "version": 1, "items": [...] }`. Каждая строка содержит:

- `approved: true` после проверки владельцем продукта, `reference` и `imageReview` — обезличенные ссылки на принятый источник коммерческих данных и документы на фотографии. В этих двух полях не должно быть имён, паролей, токенов, приватных URL или данных заказчиков.
- `sku` — официальный стабильный SKU латиницей верхнего регистра, с цифрами или дефисом. `name`, `categoryId` — публичное имя и одна из девяти категорий текущего каталога. `description` — 400–800 знаков, подтверждённые свойства и реальное сочетание.
- `priceRub` — утверждённая цена в рублях, `unit` — «шт» или «лист», `dimensions.lengthMm` и при наличии `dimensions.widthMm` — размеры. Для всех групп кроме профиля ширина обязательна. Дополнительные проверенные поля — `thicknessMm`, `weightKg`, `material`.
- `photos` — массив из 4–8 объектов с `image` и `view`. Обязательные виды: `detail`, `full`, `angle`, `installed`. Дополнительный вид: `comparison`. Используйте исходные WebP без искусственного увеличения внутри `public/catalog/approved/<папка-артикула>/`. Прямое фото фактуры не меньше 450 × 450. `installed` обозначает оригинальное фото именно этого изделия в выполненном объекте. Виртуальная визуализация не заменяет этот вид.

Сначала выполните только сухую проверку:

```bash
node scripts/catalog-import.mjs /private/owner-export.json --check
```

Когда утверждение на публикацию получено, запишите принятые позиции в дополнительный исходный реестр:

```bash
node scripts/catalog-import.mjs /private/owner-export.json --append
```

Импорт не переписывает компоненты, основной PDF или цены существующих позиций. Проверяются дубликаты SKU, путей, фото и товарных идентификаторов. После проверки сборки посмотрите изменения реестра и новых файлов до отдельной публикации. Карточки, счётчики, фильтры, галерея и фиды используют общий справочник. Товарный ID рассчитывается по принятому SKU и не меняется от названия или цены. Сверка CRM, свободного остатка и цен сделки выполняется в отдельном закрытом контуре. Не переносите полный экспорт МойСклад или исходные документы на Pages.

## Шаблон проекта

Добавляйте только подтверждённые реальные объекты в реестр `src/data/verifiedProjects.ts`. Нужны публичный заголовок и описание, площадь отделки, число дней монтажа, дата публикации, точные ID из текущего каталога с официальными SKU, оригинальная фотография с правом публикации, краткий бриф и проверяемые подробности работ. Никаких адресов клиентов и персональных данных. Разместите фото дела в `public/catalog/projects/`. Реестр создаёт карточку объекта, ссылки на материалы, обратные ссылки из товара и allowlist ресурсов. Сейчас реестр пуст: демонстрационные интерьеры остаются маркированными визуализациями.
