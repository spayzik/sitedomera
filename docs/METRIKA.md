# Яндекс Метрика для ДЕКОРАЙ

## Подключение и доступ

1. В Яндекс Метрике откройте «Счётчики» → «Добавить счётчик». Назовите его «ДЕКОРАЙ staging», укажите `https://spayzik.github.io/dekoray-preview/`. В настройках адреса поставьте ограничение приёма данных адресами, заданными для счётчика. В тестовом отчёте фильтруйте страницы по префиксу `/dekoray-preview/`, поскольку хост GitHub Pages может обслуживать и другие проекты.
2. Скопируйте числовой ID, передайте его интегратору как `VITE_YM_STAGING_ID`. ID публичный. На вкладке «Доступ» добавьте аккаунт интегратора с правами на настройку целей и просмотр тестовых записей. Пароль, OAuth-токен и cookie через задачи или Git передавать не требуется.
3. В «Настройки» → «Счётчик» включите «Вебвизор, карта скроллинга, аналитика форм». На вкладке «Вебвизор» включите запись, отключите «Записывать все поля». Отключите Advanced Matching, автоматический сбор контактов и автоматические цели. Включите «Электронная коммерция», контейнер `dataLayer`. Для ссылок сайт передаёт переходы по публичным доменам через `extLink`. Для карты кликов используется `clickmap`.
4. После настройки соберите профиль staging с `VITE_YM_STAGING_ID=<тестовый ID>` и `VITE_YM_WEBVISOR=1`. Опубликуйте его на том же preview. Production использует отдельный `VITE_YM_ID` и отдельное решение о включении Вебвизора. Заказчик подтверждает production ID для декорай.рф, ранее использовался 114347066. Тестовый профиль исключает совпадение числовых ID, production-профиль не запускает счётчик с хостов GitHub Pages.

## Реестр целей

Для регистрации создайте в тестовом счётчике по одной цели «Целевое событие» с условием «совпадает» и точным именем. Выполните указанные ниже сценарии после согласия. В графе «Кабинет» укажите статус, ID визита и время подтверждённого события. Исходное состояние всех строк — BLOCKED до тестового ID и доступа.

| Имя | Назначение | Где и когда возникает | Кабинет |
|---|---|---|---|
| `catalog_view` | Вход в каталог | Один просмотр чистого URL каталога, категории или подборки материалов | BLOCKED |
| `product_view` | Просмотр товара | Чистая страница товара или открытие отдельной карточки каталога | BLOCKED |
| `catalog_search` | Использование поиска | Непустой новый запрос при Enter или выходе из поля. Текст запроса не передаётся | BLOCKED |
| `catalog_filter` | Использование фильтров | Изменение фильтра, сортировки или сброс активных условий | BLOCKED |
| `cart_add` | Добавление в подборку | Допустимое увеличение количества товара | BLOCKED |
| `cart_remove` | Удаление из подборки | Допустимое уменьшение количества, удаление строки или очистка | BLOCKED |
| `cart_view` | Открытие подборки | Панель подборки переходит из закрытого состояния в открытое | BLOCKED |
| `calculator_start` | Начало расчёта | Первое изменение полей или выбор материала в калькуляторе | BLOCKED |
| `calculator_complete` | Получен расчёт | Первый полный валидный результат по всем добавленным материалам, включая расчёт из одних реек и профилей | BLOCKED |
| `quiz_complete` | Пройден квиз | Показ результата после последнего ответа | BLOCKED |
| `phone_click` | Интерес к звонку | Нажатие ссылки `tel:`, номер не передаётся | BLOCKED |
| `telegram_click` | Переход в Telegram | Фактический переход по ссылке Telegram, параметры черновика не передаются | BLOCKED |
| `whatsapp_click` | Переход в WhatsApp | Нажатие ссылки на WhatsApp, номер и параметры черновика не передаются | BLOCKED |
| `max_click` | Переход в MAX | Нажатие ссылки на внешний MAX. Локальная страница поиска по номеру сама не считается внешним переходом | BLOCKED |
| `external_click` | Переход на внешний сервис | Фактический переход по внешней HTTPS-ссылке. Отчёт переходов получает только origin | BLOCKED |
| `sample_request` | Начат запрос образца | Открытие окна запроса образцов | BLOCKED |
| `installation_request` | Начат запрос монтажа | Открытие окна запроса монтажа или замера | BLOCKED |
| `b2b_request` | Начат оптовый или дизайнерский запрос | Открытие окна оптового или дизайнерского запроса | BLOCKED |
| `lead_start` | Начато заполнение заявки | Первое изменение поля текущей формы | BLOCKED |
| `lead_submit` | Получена подтверждённая заявка | Первая наблюдаемая квитанция сервера после HTTP 201 или восстановления через HTTP 200 | BLOCKED |
| `lead_error` | Ошибка при отправке | Неуспешная попытка запроса или сетевой сбой | BLOCKED |

Соберите воронку из целей просмотра товара → подборки или расчёта → начала формы → подтверждённой заявки. В `dataLayer` передаются `detail`, `add`, `remove` с публичным ID товара, ценой и, для изменения количества, количеством. `purchase` требует подтверждённой платёжной интеграции. Открытие мессенджера и нажатие «Отправить» не являются заявкой или покупкой.

## Приёмка реального визита

1. В новом профиле Chromium проверьте Network до выбора, после отказа и после повторного включения аналитики. Запросы к счётчику допускаются после согласия, используют только тестовый ID и прекращаются после отзыва. При отзыве страница перезагружается. Ранее принятые провайдером данные сохраняются по его правилам.
2. Пройдите сценарий от входа по размеченной ссылке до отправки. Для проверки используйте `utm_source=yandex&utm_medium=cpc&utm_campaign=123`. Отдельно проверьте поиск по существующему артикулу и произвольный поиск. Произвольный запрос не сохраняется в URL каталога. Карточки и `dataLayer` не содержат введённого текста. Для проверки транспорта `hit` и ecommerce используйте Network и отладчик Метрики `_ym_debug=2`.
3. Пройдите синтетическую заявку на отдельном staging API, повторите запрос после контролируемой потери ответа. Проверьте один `lead_submit` при подтверждённом идентификаторе. Для проверки маскирования вводите только синтетические данные. Сравните Network с реальными событиями тестового счётчика.
4. В кабинете откройте этот визит в Вебвизоре. Убедитесь, что поисковый текст, поля формы и код тестового доступа не читаются. Проверьте карту кликов, скроллинг, аналитику форм и отчёт внешних переходов. В карте ссылок данные внешних переходов агрегируются по origin, детализация по полным URL отключена.
5. Сохраните время и ID визита, снимки отчётов без персональных данных, результаты раздельных замеров мобильного LCP с Метрикой и Вебвизором. Если видны значения полей, отключите запись и закройте приёмку только после исправления и повторного воспроизведения.

`node --test scripts/analytics.test.mjs scripts/catalog.test.mjs` проверяет локальный контракт адаптера, согласие, события, фильтры и ограничение параметров. `node scripts/cookie-consent.browser.mjs` запускает локальный тест Chromium с перехватом запроса тега и проверяет интерфейс на пяти ширинах. Для Playwright вне репозитория укажите абсолютные `PLAYWRIGHT_MODULE` и `BROWSER_EXE`. Подтверждение доставки событий и записи у Яндекса требует указанной проверки реального тестового счётчика.
