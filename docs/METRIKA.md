# Яндекс Метрика для ДЕКОРАЙ

Сборка production принимает `VITE_YM_ID`. Заказчик подтверждает счётчик для декорай.рф, ранее использовался 114347066. Сборка staging принимает отдельный `VITE_YM_STAGING_ID` и исключает номер production. Без ID скрипт счётчика не загружается.

В кабинете тестового счётчика задайте адрес GitHub Pages и ограничьте записи визитами этого стенда. Включите карты кликов и ссылок, а также электронную коммерцию через `dataLayer`. Для карты скроллинга и аналитики форм включите Вебвизор в настройках счётчика. Отключите «Записывать все поля», автоматические цели, автоматический сбор контактных данных и Advanced Matching. В сборке добавьте `VITE_YM_WEBVISOR=1` только для согласованной проверки и последующей активации. Разрешение на аналитику должно быть дано посетителем. При его отзыве счётчик останавливается и страница перезагружается.

## Цели

Создайте цели «Целевое событие» с условием «совпадает» и этими идентификаторами.

| Этап | Идентификаторы |
|---|---|
| Просмотр и выбор | `catalog_view`, `product_view`, `catalog_search`, `catalog_filter` |
| Подборка | `cart_add`, `cart_remove`, `cart_view` |
| Расчёт | `calculator_start`, `calculator_complete`, `quiz_complete` |
| Связь | `phone_click`, `telegram_click`, `whatsapp_click`, `max_click`, `external_click` |
| Намерение | `sample_request`, `installation_request`, `b2b_request` |
| Обращение | `lead_start`, `lead_submit`, `lead_error` |

Для воронки используйте просмотр товара → подборку или расчёт → начало формы → подтверждённую заявку. Подборка передаёт в электронную коммерцию только публичный ID товара, цену и количество. Покупка учитывается при подтверждённой оплате и требует согласованной платёжной интеграции. При открытии мессенджера фиксируется переход, после подтверждённой доставки backend — заявка.

## Приёмка в кабинете

1. Начните в новом профиле браузера. При отказе и до согласия проверьте отсутствие запросов счётчика. После согласия проверьте одно подключение к верному счётчику. Просмотры передают путь страницы, допустимые значения UTM и домен источника. Текст поиска, произвольные параметры URL и ссылки на черновики мессенджеров в события не передаются.
2. Проверьте в тестовом счётчике поиск, фильтры, карточку, подборку и расчёт. Проведите синтетическую заявку только через тестовое API. Ошибка и повтор после сетевого сбоя не должны создавать вторую заявку или дублировать подтверждённую цель.
3. Найдите тестовый визит, откройте запись Вебвизора и проверьте маскирование синтетических значений во всех полях заявки и в чате. Сохраните идентификатор визита, дату и обезличенное подтверждение. При любом видимом значении отключите запись и исправьте настройки перед повтором.
4. Проверьте карты и конверсию на тестовых визитах отдельно от данных заказчика.

`node --test scripts/analytics.test.mjs` проверяет вызовы адаптера, согласие и ограничение параметров. Этот тест не проверяет сохранение событий у Яндекса и запись Вебвизора.
