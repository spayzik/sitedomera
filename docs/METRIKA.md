# Яндекс Метрика для ДЕКОРАЙ

## Подключение и доступ

1. Для рабочего сайта предназначен ранее предоставленный счётчик **114347066**. Production-профиль использует `VITE_YM_ID=114347066` и `VITE_YM_WEBVISOR=1`. Загрузка тега возможна после согласия и только на каноническом HTTPS-домене.
2. Для preview создайте отдельный счётчик «ДЕКОРАЙ staging» с адресом `https://spayzik.github.io/dekoray-preview/`. Включите «Принимать данные только с указанных адресов сайтов». В тестовом отчёте фильтруйте страницы по префиксу `/dekoray-preview/`, поскольку GitHub Pages может обслуживать и другие проекты. Публичный ID передайте как `VITE_YM_STAGING_ID`. Рабочий счётчик не подставляется в preview. После получения тестового ID соберите staging с `VITE_YM_WEBVISOR=1`.
3. В каждом счётчике откройте «Настройки» → «Счётчик» и включите «Вебвизор, карта скроллинга, аналитика форм». На вкладке «Вебвизор» включите запись и выключите «Записывать все поля». Отключите Advanced Matching, автоматический сбор контактов и автоматические цели. Настройте электронную коммерцию с контейнером `dataLayer`, валюту RUB и опцию «Удалять дубли событий покупок электронной коммерции в разных визитах». [Настройки счётчика](https://yandex.ru/support/metrica/ru/general/counter-general) · [Настройки Вебвизора](https://yandex.ru/support/metrica/ru/webvisor/settings.html)
4. Код сайта включает карту кликов и точный показатель отказов. Переходы на другие сайты учитываются по origin через `extLink` для карты ссылок и отчёта «Внешние переходы». URL черновика, номер телефона и параметры платёжной ссылки в эти события не входят. [Параметры счётчика](https://yandex.ru/support/metrica/ru/code/counter-initialize.html) · [Карта ссылок](https://yandex.ru/support/metrica/ru/behavior/link-map.html) · [extLink](https://yandex.ru/support/metrica/ru/objects/extlink)
5. Для ручной проверки достаточно действующего доступа к нужному счётчику. При необходимости пригласите проверяющего через вкладку «Доступ». Для настройки целей и воронок нужна роль с правом редактирования. В проверяемой поставке статус действий в кабинете и реального воспроизведения записи — **BLOCKED**.

## Реестр целей

В разделе «Цели» каждого счётчика создайте или проверьте по одной цели типа «Целевое событие», условие «совпадает», идентификатор из первой колонки. Существующие цели с тем же идентификатором используйте повторно. В графе «Кабинет» зафиксируйте время и ID визита после проверки на отдельном тестовом счётчике. [Настройка целевого события](https://yandex.ru/support/metrica/ru/general/goal-js-event.html)

| Имя | Назначение | Где и когда возникает | Кабинет |
|---|---|---|---|
| `catalog_view` | Вход в каталог | Один просмотр чистого URL каталога, категории или подборки материалов | BLOCKED |
| `product_view` | Просмотр товара | Чистая страница товара или открытие отдельной карточки каталога | BLOCKED |
| `catalog_search` | Использование поиска | Непустой новый запрос при Enter или выходе из поля. Текст запроса не передаётся | BLOCKED |
| `catalog_filter` | Использование фильтров | Изменение фильтра, сортировки или сброс активных условий | BLOCKED |
| `cart_add` | Добавление в подборку | Допустимое увеличение количества товара | BLOCKED |
| `cart_remove` | Удаление из подборки | Допустимое уменьшение количества, удаление строки или очистка | BLOCKED |
| `cart_view` | Открытие подборки | Панель подборки переходит из закрытого состояния в открытое | BLOCKED |
| `calculator_start` | Начало расчёта | Первое изменение полей или выбор материала в калькуляторе | BLOCKED |

| `quiz_complete` | Пройден квиз | Показ результата после последнего ответа | BLOCKED |
| `phone_click` | Интерес к звонку | Нажатие ссылки `tel:`, номер не передаётся | BLOCKED |
| `telegram_click` | Переход в Telegram | Фактический переход по ссылке Telegram, параметры черновика не передаются | BLOCKED |
| `whatsapp_click` | Переход в WhatsApp | Нажатие ссылки на WhatsApp, номер и параметры черновика не передаются | BLOCKED |
| `max_click` | Переход в MAX | Нажатие ссылки на внешний MAX. Локальная страница поиска по номеру сама не считается внешним переходом | BLOCKED |

| `sample_request` | Начат запрос образца | Открытие окна запроса образцов | BLOCKED |
| `installation_request` | Начат запрос монтажа | Открытие окна запроса монтажа или замера | BLOCKED |
| `b2b_request` | Начат оптовый или дизайнерский запрос | Открытие окна оптового или дизайнерского запроса | BLOCKED |
| `lead_start` | Начато заполнение заявки | Первое изменение поля текущей формы | BLOCKED |
| `lead_submit` | Получена подтверждённая заявка | Первая наблюдаемая квитанция сервера после HTTP 201 или восстановления через HTTP 200 | BLOCKED |
| `lead_error` | Ошибка при отправке | Неуспешная попытка запроса или сетевой сбой | BLOCKED |

Добавьте отдельную цель «Целевое событие» с идентификатором `begin_checkout`. В `dataLayer` передаются `detail`, `add`, `remove`, `begin_checkout` в формате GA4 и `purchase` в формате Enhanced Ecommerce с `actionField.id` и суммой. ID товаров совпадают с `offer id` в YML. Начало оформления фиксируется один раз по ID заказа в браузере. Покупка фиксируется после ответа API со статусом оплаты и временем подтверждения провайдера. Используйте штатную цель «Электронная коммерция → Покупка» для этого события. Дополнительный `reachGoal` с тем же смыслом не нужен. [Объекты электронной коммерции](https://yandex.ru/support/metrica/ru/ecommerce/data)

В «Отчёты» → «Создать отчёт» → «Воронка» сохраните две последовательности.

- «Заявки», окно 7 дней. Шаги «Просмотр товара» (`product_view`), «Подборка или расчёт» (`cart_add` или `calculator_complete`), «Начало формы» (`lead_start`), «Принятая заявка» (`lead_submit`).
- «Онлайн-оплата», окно 7 дней. Шаги «Просмотр товара» (`product_view`), «Подборка» (`cart_add`), «Начало оформления» (`begin_checkout`), «Покупка» (штатная цель электронной коммерции). В отчёте сравните конверсию от соседнего и первого шагов.

[Настройка воронок](https://yandex.ru/support/metrica/ru/reports/funnels)

## Источники трафика

Первое посещение передаёт `utm_source` и `utm_medium` из фиксированных списков проекта и числовой `utm_campaign` длиной до 9 цифр. Используйте `utm_source=yandex|google|avito|telegram|vk|2gis|direct` и `utm_medium=organic|cpc|referral|social|email|display|qr`, по одному значению каждого параметра. Источник также определяется по origin предыдущей страницы. Сверьте визит в отчётах «Источники» и «Метки UTM». Произвольный текст запроса, `utm_term`, `utm_content` и прочие параметры из URL в отправку приложения не входят. [Конфиденциальность данных](https://yandex.ru/support/metrica/ru/general/confidential-data.html)

## Приёмка реального визита

1. В новом профиле Chromium проверьте Network до выбора, после отказа и после повторного включения аналитики. Запросы к счётчику допускаются после согласия, используют только тестовый ID и прекращаются после отзыва. При отзыве страница перезагружается. Ранее принятые провайдером данные сохраняются по его правилам.
2. Пройдите сценарий от входа по размеченной ссылке до отправки. Для проверки используйте `utm_source=yandex&utm_medium=cpc&utm_campaign=123`. Отдельно проверьте поиск по существующему артикулу и произвольный поиск. Произвольный запрос не сохраняется в URL каталога. Карточки и `dataLayer` не содержат введённого текста. Для проверки транспорта `hit` и ecommerce используйте Network и отладчик Метрики `_ym_debug=2`.
3. При готовности отдельных тестовых API пройдите синтетическую заявку и платёж на тестовых данных. В течение одного визита проверьте один `lead_submit` после подтверждённой заявки, `begin_checkout` при начале оплаты и один `purchase` после подтверждения провайдера. Обновите страницу заказа и откройте её во второй вкладке для проверки повторов. При проверке маскирования вводите только синтетические контакты. Публичное подключение формы вынесено в последующий этап.
4. В кабинете откройте визит в Вебвизоре. Проверьте маскировку поиска, полей формы, кода тестового доступа, чата, черновиков и платёжной секции. Проверьте карты кликов, скроллинга, ссылок, аналитику форм и отчёт внешних переходов. Внешние переходы передаются в разрезе origin.
5. Сохраните время и ID визита, снимки отчётов без персональных данных, результаты раздельных замеров мобильного LCP с Метрикой и Вебвизором. Если видны значения полей, отключите запись и закройте приёмку только после исправления и повторного воспроизведения.

`node --test scripts/analytics.test.mjs scripts/catalog.test.mjs` проверяет локальный контракт адаптера, согласие, события, фильтры и ограничение параметров. `node scripts/cookie-consent.browser.mjs` запускает локальный тест Chromium с перехватом запроса тега и проверяет интерфейс на пяти ширинах. Для Playwright вне репозитория укажите абсолютные `PLAYWRIGHT_MODULE` и `BROWSER_EXE`. Подтверждение доставки событий и записи у Яндекса требует указанной проверки реального тестового счётчика.
