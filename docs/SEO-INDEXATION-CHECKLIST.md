# ДЕКОРАЙ · индексация и приёмка SEO

## Исходный код и сборки

- React + Vite пререндерит главную, категории, товарные карточки, редакционные подборки, страницы услуг и статьи с полным исходным HTML. URL, SEO-метаданные, sitemap, JSON-LD и YML используют один каталог маршрутов.
- /news/ — канонический адрес статей по решению владельца. Старые /stati/ и адреса известных статей перенаправляются. /dostavka/ — канонический адрес страницы доставки. Старые /dostavka-i-oplata/, /catalog/wood/ и /offer/ имеют аналоги. URL с legacy-хэшами мигрируют в браузере, так как сервер не получает фрагмент URL.
- Канонический адрес карточки или каталога не содержит параметров. Поиск и сортировка закрыты в production robots.txt. Инвентарь, толщина, UTM и другие параметры оставляют canonical исходной индексируемой страницы. Текущий каталог помещается на одной странице. Параметр page не создаёт страницу.
- В наличии показывается подтверждённое состояние свежего снимка. В статической разметке Product/Offer остаются проверенная цена и RUB. Поле availability опущено до возможности гарантировать актуальность снимка в индексируемом HTML. Рейтинг магазина не переносится в карточки товаров.
- У staging-страниц, включая старые адреса и 404, выставлены noindex, nofollow, noarchive. Meta canonical для staging отсутствует. Поисковики должны иметь доступ к HTML, чтобы увидеть этот запрет. robots.txt на корне домена GitHub Pages управляется владельцем корневого сайта, а не проектом на подпути. Staging robots.txt не анонсирует карту production.
- Сборка и верификатор получают один профиль в окружении. При необходимости побайтово повторить YML задайте одинаковый SOURCE_DATE_EPOCH (число секунд Unix). Для отправляемого в сервис фида используется дата фактической сборки.

## REG.RU после Owner GO

1. Проверить TLS для apex и www, наличие обоих имён, фактическую панель управления, document root и обработку Apache. По документации REG.RU для ispmanager переадресация HTTP → HTTPS настраивается в панели после установки SSL. Используйте панель при завершении TLS на прокси. В подготовленном шаблоне есть альтернативный выключенный блок для Apache, если реальный внешний HTTPS даёт HTTPS=on именно в Apache. [REG.RU](https://help.reg.ru/support/hosting/redirekty/redirekt-s-http-na-https-dlya-linux)
2. В согласованное окно установки разместить подготовленные правила из host-settings/apache.htaccess в подтверждённом webroot после резервной копии действующей конфигурации. Проверить 301 для www и переходов со старых адресов, конечную косую черту и index.html, коды 200 для всех sitemap URL, сохранение query и HTTP 404 для вымышленного пути. Устранить петли и лишние переходы перед индексацией.
3. Проверить origin и canonical страницы, JSON-LD валидатор Яндекса и реальные даты обновления в sitemap. Владелец или уполномоченная роль подтверждает домен в Яндекс.Вебмастере и Google Search Console, выставляет регион Москва и подключает фактические sitemap.xml и YML. Занести исходные позиции и частотность через Вордстат. Проверить, что preview исключён из поиска.
4. Согласовать владельцев Яндекс Бизнес, 2ГИС, Google Business и остальных площадок. После Owner GO привести контакты, название, часы, фото и предложения к одному подтверждённому набору. Для Яндекс Бизнес проверить существующую карточку 55177309503 и право управления. Вести календарь из 2–4 статей и готовых проектов в месяц. Публикации по объектам требуют фото и согласованных артикулов.

## IndexNow после Owner GO

В защищённой настройке сборки production задайте DEKORAY_INDEXNOW_KEY. Допустимы 8–128 ASCII-букв, цифр или дефисов. Сборка создаст одноимённый открытый текстовый файл в корне dist. Staging отключает эту функцию. Ключ служит публичным подтверждением владения сайтом, для него используют отдельное значение и не переиспользуют пароли или токены магазинов.

После публикации проверенного production-артефакта запустите в том же окружении npm-проекта `node scripts/indexnow.mjs /catalog/ /news/`, указав только изменённые канонические пути. Команда проверяет доступность файла на production HTTPS, отбрасывает дубли и принимает только маршруты витрины. Из сборки никаких запросов в поисковики нет. Ответ HTTP 200 или 202 означает приём уведомления. Индексация подтверждается отдельно в Вебмастере. [Протокол IndexNow](https://www.indexnow.org/documentation) · [API IndexNow в Яндексе](https://yandex.ru/support/webmaster/ru/indexnow/reference)

## Условия подтверждения

Оценить LCP, INP и CLS на реальном хостинге на мобильных страницах. Подтвердить после запуска фактический обход, статус страниц и позиции в отчётах. Для ванной, фартуков и коммерческих объектов требуются технические сведения о пригодности конкретных SKU, включая требования к эксплуатации и монтажу. Новые цветовые страницы требуют подтверждённых декоров, а товарный рейтинг требует отзывов по конкретному SKU.
