# Товарные фиды ДЕКОРАЙ

| Витрина | Адрес после запуска | Правило наличия |
|---|---|---|
| Поиск по товарам | `https://декорай.рф/yml.xml` | Передаёт только позиции, доступные к заказу, с `available="true"` и подходящим изображением. Дата в RFC 3339 с часовым поясом. |
| Директ | `https://декорай.рф/yml-direct.xml` | Передаёт все 45 позиций с явным `available`. Для кампании с товарами в наличии установите фильтр по `available=true`. Дата формирования в московском времени, формат `YYYY-MM-DD hh:mm`. |

Поиск по товарам исключает неподтверждённые предложения. Директ считает товар доступным при пропуске атрибута, поэтому атрибут есть на каждом предложении. Данные SKU, цена, фото и canonical URL берутся из той же версии каталога, что и витрина. W8 сохраняет свои идентификаторы предложений. Метрика использует те же идентификаторы для электронной коммерции. [Правила Поиска](https://yandex.ru/support/merchants/ru/offers.html), [структура фида](https://yandex.ru/support/merchants/ru/connect/form-feed), [правила Директа](https://yandex.ru/support/direct/ru/feeds/requirements-yml).

## Установка после отдельной приёмки хоста

1. Разместите `web/` из production ZIP. Установите `api-entry/commerce.php` как `webroot/api/commerce.php`. Используйте маршруты для `/yml.xml`, `/yml-direct.xml` и `/generated/commerce.json` из `host-settings/apache.htaccess`. В архиве уже есть два резервных статических файла. Поиск в них не содержит предложений, у Директа все 45 значений `available="false"`.
2. Используйте исходник той же версии, что и сайт, Node.js 24 и текущие настройки read-only синхронизации. Укажите `DEKORAY_INVENTORY_MANIFEST_FILE` в закрытом каталоге для вывода штатного манифеста. Дополнительно задайте абсолютные пути `DEKORAY_COMMERCE_POLICY_FILE` и `DEKORAY_COMMERCE_STATE_FILE` вне Git и webroot. Второй путь должен быть `dekoray-leads/commerce-state.json` рядом с закрытой конфигурацией PHP. Например, для webroot `/srv/dekoray/htdocs/dekoray.rf` это `/srv/dekoray/dekoray-leads/commerce-state.json`. Каталог требует 0700, файл требует 0600. PHP и задача обновления должны иметь доступ к нему под разрешённым пользователем.
3. Заполните закрытый `DEKORAY_COMMERCE_POLICY_FILE` по шаблону ниже. Юридическое наименование должно быть утверждено для публичного фида. Проставьте фактические условия курьерской доставки и самовывоза. В `approvedPriceMinor` указывайте подтверждённые к продаже позиции и их цену в копейках с ключами ID сайта. Сверьте их с коммерческими условиями, действующим способом заказа и ценой каталога. Пустой список запрещает публикацию положительных признаков.

```json
{
  "version": 1,
  "legalName": "<подтверждённое полное наименование продавца>",
  "delivery": true,
  "pickup": false,
  "approvedPriceMinor": {}
}
```

4. После успешной штатной публикации остатков запустите дополнительную команду. Запускайте обе команды последовательно в одном задании без перекрытий. Действующую задачу оставьте до разрешения владельца. Права и параметры текущего задания приведены в [MOYSKLAD-INVENTORY.md](MOYSKLAD-INVENTORY.md).

```sh
npm run sync:inventory -- publish && node server/inventory/refresh-commerce.mjs
```

Дополнительный GET запрашивает `freeStock` только по сопоставленным и согласованным позициям. Остатки других складов не прибавляются. Резервы без выбранного склада вычитаются из выбранного запаса. Для положительного статуса нужны минимум одна единица в физическом и свободном остатках, сопоставленный артикул и совпадающая утверждённая цена. Снимок связывает оба XML, время актуальности и статус заказа. Он заменяется одной атомарной операцией. PHP немедленно переходит к резервным XML при несовпадении хеша текущих остатков или каталога, а также по истечении 45 минут. Просроченный положительный остаток не публикуется даже при остановленном задании. [Контракт МойСклад](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/reports/_report_stock.md).

Статический HTML сохраняет цену и `Offer` без утверждения о наличии. После загрузки свежих данных карточка сообщает, можно ли заказать позицию. `Offer` получает `InStock` при том же подтверждении, что и в фиде, `OutOfStock` при свежем физическом нуле. При неизвестном наличии поле опускается. В preview публикуются только резервные XML.

## Проверка и добавление в кабинет

- На разрешённом тестовом хосте проверьте свежий положительный, нулевой и неизвестный остатки, истечение срока и смену версии каталога. Сверьте соответствующие цену, URL, фотографию и признак наличия в карточке и фиде. Изменение цены требует сборки сайта из согласованного источника и повторного подтверждения позиции в закрытой конфигурации.
- Фотографиям 9 из 45 позиций хватает пикселей для Поиска по товарам и 7 из 45 для технического порога Директа. Для остальных нужны оригиналы подходящего качества. Директ отдельно проверяет композицию. [Изображения для Поиска](https://yandex.ru/support/merchants/ru/offers.html), [изображения для Директа](https://yandex.ru/support/direct/ru/feeds/requirements-yml).
- После запуска подтвердите, что оба HTTPS URL возвращают `200` и XML, а ссылки из фида открываются без авторизации. В Вебмастере используйте «Товары» → «Фиды». В кабинете Яндекс Товаров откройте «Товары» → «Источники данных» → «Фиды» → «Добавить» и укажите `/yml.xml` с регионом Москва при подтверждённых условиях реализации. Дождитесь проверки данных. URL `/yml-direct.xml` добавляется отдельно через фиды Директа. [Добавление фида](https://yandex.ru/support/merchants/ru/connect/feed-load).

Адресная локальная проверка через PHP CLI и синтетические остатки запускается командой `node --test scripts/product-feed.test.mjs server/inventory/commerce.test.mjs`. Укажите `DEKORAY_PHP_BIN`, если PHP отсутствует в PATH. Хост, рабочие остатки и кабинет в локальной проверке не задействованы.
