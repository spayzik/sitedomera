# Синхронизация отзывов Авито

Сайт остаётся статическим. `npm run sync:avito` выполняется только локально или в CI **до** `npm run build`. Браузер загружает только файл своего домена `generated/avito-reviews.json`; к `api.avito.ru` не обращается. Данные из Авито не являются частью env Vite. Никаких ключей с префиксом `VITE_` создавать нельзя.

## Контракт и проверка доступа

Используемая схема из каталога Avito Ratings API: `POST /token` с `grant_type=client_credentials`, затем `GET /ratings/v1/info` и `GET /ratings/v1/reviews?offset=0&limit=12` с Bearer token. В описании операции `reviews` возвращаются активные отзывы; обязательные `offset` и `limit`, максимум `limit=50`. Читаются `rating.score`, `rating.reviewsCount`, `reviews[].score`, `reviews[].text`, `reviews[].createdAt` (Unix seconds). Схема указывает Client Credentials как один из допустимых способов для обоих GET-методов.

На момент подготовки прямой доступ к [официальному разделу Ratings](https://developers.avito.ru/api-catalog/ratings/documentation) был недоступен в рабочей среде. Поля и методы дополнительно сверены с [публикацией OpenAPI-контракта](https://apis.io/apis/avito/avito-ratings-api/) и [копией раздела документации](https://github.com/MissiaL/avito-api/blob/main/references/sections/ratings.md), которые обозначают источником официальный каталог Avito. Это не заменяет пробный запрос с доступом владельца. Числовой rate limit для этих методов подтвердить не удалось; скрипт делает только три запроса за запуск и при HTTP 429 сохраняет прежний снимок.

## Запуск

1. Владелец подтверждает соответствие API-ключей публичному профилю из `CONTACTS.avito` и право доступа к Ratings API.
2. Секреты `AVITO_CLIENT_ID` и `AVITO_CLIENT_SECRET` передаются только через локальное окружение или GitHub Actions Secrets. В логах их значения не выводятся.
3. Выполняются `npm run sync:avito` и затем `npm run build`. Расписание и production deployment на REG.RU настраиваются в отдельной итерации.

При отсутствии обоих секретов синхронизация пропускается без ошибки, а сайт показывает ссылку на Авито. При неполной конфигурации, HTTP-ошибке, таймауте или неверной схеме скрипт завершается с ошибкой и не заменяет существующий JSON. Данные проверяются до атомарной записи через временный файл. Пустой или полностью непригодный ответ не перезаписывает старые отзывы. Снимок с действительными отзывами сохраняется в `public/generated/avito-reviews.json` и копируется Vite в `dist`.

Начальный JSON содержит только `null` и пустой список: это **не** реальные отзывы. Он обеспечивает сборку и fallback без секретов. Синтетические примеры находятся исключительно в `scripts/fixtures/` и используются только тестом `npm run test:avito`; в production они не публикуются.

## Публикуемые данные

Публикуются: источник, время синхронизации, общий рейтинг, число отзывов и до восьми карточек с оценкой, датой и текстом. Текст ограничен 600 символами; похожие на email и телефон фрагменты скрываются. Имя автора, ID отзыва и объявления, изображения, ответы продавца и прочие поля сырого ответа не публикуются. React выводит текст с обычным escaping.

`updatedAt` служит для проверки свежести. Старый, но валидный снимок пока остаётся видимым, а ссылка на актуальные отзывы на Авито доступна всегда. Перед production запуском нужно определить приемлемую частоту синхронизации и проверить фактические квоты аккаунта.
