# ДЕКОРАЙ. Физические остатки одного склада

## Граница интеграции

МойСклад отдаёт физический остаток, Node формирует отдельный JSON, браузер читает один снимок для всех карточек, модалки, корзины и калькулятора. Цены, изображения, каталог и заявки используют свои действующие источники. Новый узел не вызывает код заявок и выполняет только GET.

Публичный статус в дизайне ДЕКОРАЙ занимает одну строку рядом с ценой/характеристиками, со спокойной точкой и текстом, понятным без цвета. Использованы текущий интерфейс и его токены. Значение в карточке, модалке и подборке одинаково. В модалке указано московское время подтверждённого снимка. Подборка и запрос наличия доступны при любом статусе.

## Контракт МойСклад

- [Склады](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_store.md) — GET entity/store. Один склад подтверждается по точному адресу Москва, Алтуфьевское ш., 37с1 или явному UUID, который владелец сверил в кабинете. Склад с указанным, но неподтверждённым адресом отклоняется даже при явном UUID. Для публикации UUID обязателен.
- [Ассортимент](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_assortment.md) — GET entity/assortment с ассортиментом и модификациями, заголовком assortmentWithoutStock и пагинацией limit/offset. Дубли и неполные страницы останавливают импорт.
- [Единицы](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_uom.md) — GET entity/uom. Известные обозначения штук и листов сопоставляются без пересчёта. У модификации используется единица подтверждённого родителя. Отличающаяся или отсутствующая единица даёт неизвестный статус. Дробное число при совпавшей единице показывается как получено.
- [Краткий складской отчёт](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/reports/_report_stock.md#L646-L714) — GET report/stock/bystore/current со stockType=stock, include=zeroLines, withRecalculate=true и фильтром storeId + список assortmentId. Ответ — один массив. freeStock / reserve / quantity не участвуют в числе. Сопоставляется id из ассортимента с assortmentId. Другой склад, чужой ID, повтор или нарушение формата блокируют замену файла. При пропуске строки импорт проверяет [полный отчёт по складам](https://github.com/moysklad/api-remap-1.2-openapi-specification/blob/master/src/paths/reports/stocks/stock-bystore.yaml) с фильтром выбранного склада и stockMode=all. Берётся только явный `stock` для точного товара или модификации на выбранном складе. После проверки пропуск строки, null или отрицательное число показываются как неизвестные.
- [Лимиты](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/_restrictions.md) — запросы последовательно, с интервалом не меньше 300 мс между стартами. При 401/403/429, тайм-ауте или повреждённом JSON следующий запуск выполняется по штатному интервалу.

## Подтверждение сопоставления

В закрытом файле DEKORAY_INVENTORY_MAP_FILE допускается объект с ключами canonical product ID. Значение каждой записи — объект с полями id (UUID из rows[].id) и type (product или variant). Запись заполняет владелец или оператор после подтверждения товара. Для остальных карточек допустим только однозначный официальный артикул в обеих системах. Спорные, отсутствующие и дублированные артикулы, комплекты и архивы не создают публичный остаток. Код и название не считаются доказательством. Родитель с модификациями не подменяет остатки варианта.

## Запуск через защищённую среду

1. Node.js 24. В опции Node 22 требуется актуальная версия с поддержкой встроенного чтения TypeScript.
2. Назначить MOYSKLAD_API_TOKEN только в защищённой среде процесса. Нужны права чтения каталога, складов, единиц и остатков. Можно назначить подтверждённый MOYSKLAD_STORE_ID. При его отсутствии preflight пытается найти единственное точное совпадение адреса.
3. Выполнить npm run sync:inventory -- preflight. По умолчанию выдаёт только сводку и не записывает файл. Путь DEKORAY_INVENTORY_MANIFEST_FILE позволяет сохранить закрытый диагностический манифест с реальными UUID, результатами сопоставления и остатками для сверки владельцем. Хранить его и входной map вне репозитория и webroot, с правами доступа только оператору. При использовании любого закрытого файла команда требует DEKORAY_INVENTORY_WEBROOT, чтобы проверить его размещение.
   В ручной карте значение `null` исключает подтверждённый конфликт артикулов. Для отдельно проверенной панели запись `{ id, type: 'product', singleSheetName }` допускает учёт `1 шт. = 1 лист`. `singleSheetName` должен точно совпадать с названием проверенной карточки МойСклад. Импорт также сверяет её артикул, единицу учёта и отсутствие упаковок и модификаций.
4. После согласования среды выбрать отдельный единичный запуск npm run sync:inventory -- publish. Он требует подтверждённого MOYSKLAD_STORE_ID, токена в защищённой среде и DEKORAY_INVENTORY_WEBROOT с существующим generated/. Обновляет ровно generated/inventory.json через временный файл и rename в той же директории. Снимок проверяется целиком, для каждой каталожной позиции, затем меняется одним rename. Путь должен быть доступен процессу на файловой системе с атомарным rename.
5. Настроить один экземпляр задания без перекрытий каждые 15 минут в планировщике подтверждённого рантайма. Например, на отдельном Linux-сервисе с прямым доступом к webroot — systemd timer с OnCalendar=*-*-* *:00/15:00 и одноимённый oneshot service. При внешней доставке нужен подтверждённый отдельный transport с атомарной заменой, доступ только к stock snapshot, проверка MIME и политик кэша. Успешная загрузка полного архива через ispmanager не является подтверждением такого канала.
6. После появления первого валидного снимка собрать статический frontend с VITE_DEKORAY_INVENTORY=1. Настроить на JSON Cache-Control: no-store, application/json и отдачу только с origin витрины. Обычная сборка не включает JSON остатков. При обновлении файлов сайта сохранить уже размещённый generated/inventory.json.
7. На isolated staging сверить два успешных запуска и чтение JSON браузером, включая пропажу свежести после остановки задания. Публикация на действующем REG.RU и включение задания требуют независимого Chief review.

Браузер обновляет снимок раз в две минуты, когда вкладка видима, и при возвращении к ней. Через 45 минут от времени stock запроса число сменяется на «Наличие уточняется». При сбое чтения сохраняется последний успешно проверенный снимок, пока он свежий. Раздельные вкладки читают единый опубликованный источник. В сборке с выключенным флагом сайт показывает неизвестный статус без сетевого запроса. Публичный JSON содержит только ID сайта, разрешённую единицу, остаток либо причину неизвестного статуса и время снимка. UUID склада и товаров остаются в закрытом манифесте.

## HOLD и проверка

- MOYSKLAD_HOLD для заявок сохраняется. Непроведённый customerorder из изолированного теста не содержит полей резерва и движения. Правила живого аккаунта могут отдельно резервировать товары при создании заказа. До сверки сценариев кабинета нельзя включать создание заявки в МойСклад. [Шаблоны сценариев заказа](https://support.moysklad.ru/hc/ru/продажи/шаблоны_сценариев_для_заказов_покупателя)
- npm run test:inventory запускает адресные тесты и сценарий HTTP заявки: 18 листов, выбор 5, заявка, остаток 18, затем отдельное изменение провайдера до 13. Данные синтетические и существуют только в тестах.
- Для действующей витрины подтверждена ручная загрузка статики на REG.RU. Токен в проверенной среде отсутствует, склад и право чтения не подтверждены, runtime и доставка снимка пока не доказаны. Не запускать production scheduler до закрытия этих пунктов.
